## Meaning of useless

A candidate is unnecessary only when evidence supports its provenance, regeneration or retained equivalent, inactivity, and lack of current use. Age and size alone never authorize deletion. Defaults: 90 days for repository artifacts and environments, 30 days for recognized user caches. Thresholds are configurable. Missing permission, truncated enumeration, or uncertain activity must remain visible and block eligibility rather than masquerade as a complete scan. Timestamps are activity proxies, not proof of non-use.

| Detector | Evidence and outcome |
| --- | --- |
| Repo environments | Recognized `.venv`/`venv` containing `pyvenv.cfg`; project dependency specification; old source tree plus Git reflog/activity; no tracked files in artifact; ignored; no running process in project. Preserve source and Git/worktree metadata. |
| Build/test caches | Allowlisted generated dirs such as Python bytecode, pytest/mypy/ruff caches, node_modules with lockfile, Xcode DerivedData; stale, inspectable, reproducible, not tracked. Reports/screenshots/logs with unique evidence are review-only. Never guess that `data`, arbitrary `dist`, SQLite, or arbitrary tmp directories are disposable. |
| App remnants | Inventory bundle IDs from /Applications, /System/Applications, ~/Applications; show possible orphan cache/preferences/support records. Absence is uncertain (external apps/plugins), so support/preferences are report-only. Fresh inventory before any app-associated eligible action. |
| Older apps | Group same bundle ID, compare versions, report older copies for manual review. No automatic app removal. |
| Duplicates | Explicitly scoped roots; regular file size grouping then streamed SHA-256; stable fingerprints; exclude same inode/hardlinks, cloud roots/placeholders, Photos/library bundles, app bundles, backups, credentials, Git, databases; fixed visible keeper protected; rehash keeper before action. No content reads outside specified roots. |
| macOS caches | Report-only inventory /Library/Updates and Content Caching with supported manual remediation. Never remove update staging, SIP paths, snapshots, simulator devices, Docker disks, or VM images. |

## Search and presentation

Read-only targeted filesystem traversal, bounded depth/file budget, no following symlinks or crossing mounts; permission and budget failures reported. Explicit repo and duplicate roots configurable by flags/config; practical defaults for standard user cache and developer roots. Exclude own state, backups, cloud, credentials, photos, app bundles and Git internals. Fingerprint candidates including descendants and directory identity. Show logical and allocated bytes as estimates; APFS clones/compression/snapshots preclude promised savings. Size totals must not double-count overlapping candidates or hard links. Process snapshot through macOS lsof, including cwd, open files and executables, scoped to current UID's non-zombie processes; detect tool failure/incompleteness and fail closed for mutation. Restrict mutations to current-user-owned data and disclose that system/other-user process visibility is outside this check. Zombies have no live descriptors; irrelevant special-device/kqueue descriptors do not imply candidate file use, but inaccessible REG/DIR descriptors remain blockers. Block processes using any part of project for repo candidates; do not rely solely on file mtime or HEAD author date.

CLI supports scan/export JSON, review/TUI, selected dry-run/apply, quarantine list, restore and separate purge. TUI: keyboard navigation, sort/filter, detail pane containing full path/evidence/blockers/keeper/regeneration hints, no default selection, review-only items unselectable, selection summary and exact typed confirmation before moving. Persistent approval is bound to exact fingerprints and schema, not arbitrary paths in imported JSON. Friendly non-TTY failure/help; no ANSI/control injection from filenames. Demo fixtures make the review experience immediately inspectable.

## Safe execution and recovery

No `rm -rf` or privilege elevation. Fail closed on stale/untrusted plans, altered files, symlink ancestors, overlapping selections, new tracked files, missing keeper, active usage, inaccessible descendants, wrong owner or volume. Validate paths at execution independently of plan claims. Use private same-volume quarantine (default user state directory), atomic no-overwrite renames; cross-volume moves blocked. Durable write-ahead per-item journal with fsync, identity fingerprints and recoverable interrupted states. Crash between rename and journal completion must be reconciled. Restore only into an absent original path, no overwrite or unsafe ancestors. Purge only exact verified quarantine-owned items with a second typed approval; no auto purge and no age-only purge. Concurrent scan/mutation locking as appropriate. Record per-item outcomes, original paths, approvals and observed filesystem free-space change. Quarantine itself frees zero bytes and must say so.

## Activity check investigation

Observed issue: initial real `ps -axo pid=` plus all-account `lsof` reported 174 stable processes with missing cwd and inaccessible descriptors. A UID-scoped probe reduced missing processes to three, each with `Z` / `<defunct>` status. All twelve revoked descriptor markers in the probe belonged to PID 4953, ChatGPT. The ad-hoc type probe retained type between records, so its apparent CHR/KQUEUE/DIR classification is not reliable evidence; missing descriptor types must remain unknown and blocking. Local `man 2 revoke` documents invalidation of special-device descriptors, but does not establish safety for these unresolved handles.

First principles: the executor mutates only current-user-owned files, with no elevation. Its activity boundary must identify live processes in the relevant account using a candidate, preserve genuinely unknown access as a blocker, and state its coverage limits. System-account processes invisible to the user and terminated zombies cannot establish that a selectable user-owned candidate is in use. Unknown live file access cannot establish that it is unused either.

Five whys: (1) mutation was universally blocked because completeness required every system PID to have visible file data; (2) that mismatch propagated because `parse_lsof` compared the unrestricted ps inventory against unprivileged lsof coverage; (3) the collector had not defined an account/lifecycle boundary; (4) this host runs inaccessible system processes, three stable zombies and ChatGPT with revoked handles; (5) the product contract expects useful, unprivileged cleanup of user-owned data, while refusing genuinely missing relevant evidence. The fix belongs in the activity collector and its documented contract, not the executor's refusal rule.

Verification: compare fresh before/after UID inventories excluding zombie status; keep unknown REG/DIR or missing-type access as a real failure, ignore only demonstrably irrelevant special descriptors, test malformed/truncated inventories, and exercise actual macOS refusal if the unresolved ChatGPT handle persists. Diagnostics must name the owning PID, command and descriptor. Do not inject a complete snapshot into a production invocation. Restarting the affected application is a possible manual remedy; the build must not do it automatically.
