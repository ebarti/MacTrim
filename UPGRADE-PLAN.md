# MacTrim: cleanup coverage and storage exploration

User outcome: replace the sparse bespoke curses interface with a colorful library-based TUI; reliably discover stale merged Git worktrees and uninstalled application leftovers as well as existing artifacts; provide graph and list storage views starting at `/`. This supersedes the earlier stdlib-only UI constraint.

## Investigation before fixes

First principles: discovery inventories and measures objects; classification establishes ownership, regeneration or incorporation and blockers; approval selects exact objects; execution independently revalidates and journals recoverable state transitions. Read-only storage measurement must be able to inspect system-owned data without granting cleanup authority. Missing evidence is unknown, never zero or safe. A category must remain visible when another category is large/inaccessible.

Observed evidence at base 2f855acc69a3bcb9a053dd251b89a3d30d162afe: scanner.py has no Git worktree registry detector; defaults omit Codex worktree roots and ~/.cache, ~/.npm. All detectors consume one Budget and report() fingerprints/hashes even non-actionable data. A 100K live default scan exhausted in repository artifacts before caches; targeted scans found 444 repo items and 190 cache paths. apps() regards bundle absence as possible uninstall (404 predominantly system preferences) and older-app compares unknown/equal versions. activity.py takes non-atomic ps/lsof snapshots and observed 1-4 missed processes; global issues suppress all actions. Existing cleanup lifecycle has important changed-content, credentials, process argv, recovery and exclusive-rename guards that must remain.

5 Whys: (1) users see mainly environments because (2) discovery spends the shared budget in repositories before reaching other categories and worktrees have no detector; (3) generic traversal couples measuring, hashing and eligibility instead of typed evidence; (4) the original narrow generated-artifact implementation was used as a whole-Mac inventory; (5) coverage and confidence were not independently represented or verified against representative real Mac data. The owning layers are detector orchestration/evidence, measurement, process snapshot reconciliation, and presentation; changing age thresholds or merely coloring old rows would not repair coverage.

Failure dynamics: data-dependent category starvation, environment-dependent permissions/hardlinks/APFS aliases, concurrent process churn, and misleading absent-owner/version heuristics. Repeated live scans and representative mixed fixtures are needed.

## Material design decisions

1. Use Textual with Rich (verified Textual PyPI 8.2.8 supports Python >=3.9). Use native widgets/Tree/DataTable/TabbedContent/ProgressBar/Rich bars rather than hand-written event/render loops. Maintain existing CLI entry points and signed manifest/executor guards. Add one obvious `tui`/default launch and `storage` entry. Provide an isolated project environment + runnable launcher, clear dependency installation instructions; actually install it locally for user use.
2. Two primary modes/tabs: Cleanup and Storage. Cleanup has category counts, status labels plus semantic colors, sortable/searchable/filterable rows, evidence/blocker/detail panel, selected totals, progress/cancellation, fresh validation and exact typed approval. Retain nothing selected initially; report-only cannot be selected. Read-only initial discovery must run in background, show partial results/progress, and never freeze navigation.
3. Storage starts at `/`: shared dataset drives proportional size bar chart and sortable directory/file list. Drill down, parent/root navigation, breadcrumbs, refresh and logical/allocated view; selecting a chart/list entry points at the same node. Lazy/cancellable background metadata-only measurement, never hashes contents. Show measured/partial/denied/skipped/unknown explicitly; byte totals are lower bounds when incomplete. Do not follow symlinks, hydrate dataless/cloud files, enumerate virtual trees, or double-count hardlinks/firmlink aliases. On macOS preserve useful `/Users` and `/Applications` visibility despite the system/data volume split; mark mount/alias boundaries and avoid redundant `/System/Volumes/Data` totals. Storage must expose protected/system directories for read-only exploration, never hand them to cleanup automatically. Display filesystem free/used capacity separately from summed directory estimates (APFS caveat).
4. Separate cheap size/activity inventory from expensive content fingerprints; mutation-eligible objects still need signed exact content evidence and fresh revalidation. Bound detectors/subtrees independently and publish per-category/per-root coverage, not one global starvation or unrelated-error veto. Do not silently weaken evidence requirements within the selected candidate scope. Fix override config validation order. Hardlinks/special files may be measured read-only but remain blocked for mutation as required.
5. Git worktrees: discover repositories plus registered worktrees via safe `git worktree list --porcelain` grouped by common Git directory, including default ~/.codex/worktrees and ~/.codex-workspaces/worktrees discovery. Show linked path, branch/detached/head, default target/ref and merge proof; merged means stale independently of age. Use proven HEAD incorporation into resolved default branch; query GitHub merged PR for squash merges when authenticated, exact PR head match required. Locally cached refs carry freshness/limitations; uncertain squash/target evidence must be review-only, not a guessed merge. Respect configured worktree roots for actions; show out-of-scope registrations as review. Protect primary/canonical/current checkout, dirty/untracked/meaningful ignored contents, active cwd/open paths/argv, locked trees, submodules, unknown evidence and unique commits. Never delete branches or prune unrelated registrations.
6. Worktree actions must use Git-aware lifecycle (Git's existing worktree move/remove) with exact approval, signed journal, same-volume quarantine, recovery ref where needed, registry consistency checks, restore to absent original via Git, and separate purge approval. Generic rename cannot silently strand Git metadata. Fail closed if git operation cannot be made safely recoverable. Mutations only in disposable fixture repos during this assignment. If genuinely unavoidable protocol risk is found, escalate a precise design question to main; do not silently omit the planned lifecycle or weaken guards.
7. App leftovers: inventory installed app bundle identity plus helpers/extensions and relevant running/service ownership. Exclude Apple/system components from uninstall guesses; retain shared vendor ownership and incomplete-inventory uncertainty. Map exact bundle IDs and evidence-backed human folder aliases across user Caches, Preferences, Application Support, Logs, Saved Application State and Containers where readable. Explain detected owner and why absence is uncertain. Present likely vs uncertain leftovers and sizes. Unknown/equal versions are duplicate app copies, not older versions. Preferences/support/user data remain manual review unless the user explicitly confirms the retired owner and exact scope; stale proven regenerable owned cache may use normal signed cleanup. A general root explorer does not authorize removing personal app data. Keep macOS update caches as measured system-managed records with supported OS guidance.
8. Activity: reconcile bounded process lifetimes/retry ps+lsof churn; surviving unknown/revoked evidence remains fail-closed. No production activity bypass or assumption that one successful snapshot proves stability. Show reasons and retry control clearly.

Native `git worktree move` can reinterpret an occupied target as a parent, native recursive `remove` cannot enforce an approved descendant inventory, and native live-common `repair SELECTED_PATH` can rewrite unrelated pointers. Main approved exact-slot descriptor-anchored exclusive rename, durable admin recovery snapshot, exact captured admin/gitdir back-pointer isolation/replacement, approved-inventory content purge and captured-admin-only registry reconciliation. Selected .git remains validated/unchanged; unsupported relocation layouts block. Content-purged is a required durable milestone before admin deletion; absence alone is ambiguous. Branches/shared refs/objects and unrelated metadata remain intact. See README and disposable protocol regressions.
